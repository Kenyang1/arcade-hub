# Set up the repo so all three of us can build in parallel

- **Status:** draft
- **Owner:** Kenyang (coordinator), with Soham and Khoi on their steps
- **Milestone:** M0 Setup, Oct 25–31 (see docs/spec.md)
- **Date:** 2026-10-21
- **PR:** <link once opened>

## Goal
By Oct 31, each of us can clone the repo, run the web app, the API and MongoDB
locally, and see CI pass on a PR. A homebrew game plays in the browser through
EmulatorJS, and a save state round-trips. The three contracts in the spec are
agreed, so M1 work can start in parallel on Nov 1.

## Context
The repo starts with `CLAUDE.md`, `docs/spec.md`, `docs/games.md`, this plan,
the PR template, `.gitignore`, `.gitattributes`, `.env.example` and
`docker-compose.yml`. No application code exists yet. Layout and commands are
defined in `CLAUDE.md`; build to match them exactly.

## Approach
Scaffold each workstream's folder with the smallest thing that runs and passes
its checks, then wire CI to run those checks. Pages and API share types
through `web/src/lib/types.ts` and `api/ArcadeHub.Api/Contracts/`, written
together from the spec's API table. The EmulatorJS spike runs in a plain page
inside the React app, so we learn early whether save states can be pulled out
and loaded back.

Rejected: Next.js for the web app (we don't need server rendering and the API
is .NET), and a separate repo per workstream (contract changes would need
coordinated PRs across repos).

## Steps
- [ ] **Repo on GitHub** (Kenyang): `git init`, first commit of the starter
      files, push to a new GitHub repo, add Soham and Khoi, create the project
      board.
- [ ] **Web scaffold** (Kenyang): Vite + React + TypeScript in `web/` with pnpm.
      Scripts: `dev` (proxy `/api` to `http://localhost:5080`), `lint`,
      `typecheck`, `build`, `emulator:fetch` (downloads a pinned EmulatorJS
      release into `web/public/emulatorjs/`, cross-platform, no bash-only
      commands). Create `src/lib/types.ts`, `api.ts`, `mocks.ts`,
      `emulator.ts`, and stub routes: Catalog, Game details, Play, My Saves,
      Sign in.
- [ ] **EmulatorJS spike** (Kenyang + Khoi): a `/spike` route that loads one
      homebrew game from `docs/games.md`, exports a save state as bytes, and
      loads those bytes back after a page reload. Record what worked under
      Decisions. Remove the route before M1 ends.
- [ ] **API scaffold** (Soham): `api/ArcadeHub.sln` with `ArcadeHub.Api`
      (Swagger at `/swagger`, `ProblemDetails`, `GET /api/health`),
      `ArcadeHub.Core` (Mongo client from `Mongo__ConnectionString`, the four
      collections from the spec as models), `ArcadeHub.Jobs` (console app with
      `idle-sweep`, `prune-autosaves`, `import-games` commands that log
      "not implemented yet"), `ArcadeHub.Tests` (xUnit, one passing test).
- [ ] **Contracts** (Soham + Kenyang, contract PR): DTOs in
      `api/ArcadeHub.Api/Contracts/` and matching `web/src/lib/types.ts` for
      every endpoint in the spec's API table; `mocks.ts` returns M1 catalog data
      in that shape. Both review.
- [ ] **CI** (Khoi): `.github/workflows/ci.yml` runs the checks under Commands
      in `CLAUDE.md` on every PR (web lint, typecheck, build; dotnet build and
      test). Docker builds are added in M1.
- [ ] **Local Kubernetes** (Khoi): Docker Desktop Kubernetes (or kind) running
      on all three laptops; `infra/k8s/namespace.yaml` for `arcade`;
      `infra/k8s/README.md` with setup steps, including installing
      metrics-server.
- [ ] **Branch protection** (Khoi): `main` requires a PR, one approval and a
      passing CI check; no direct or force pushes.

## Decisions
| Decision | Why | Rejected |
| --- | --- | --- |
| Vite + React + TypeScript, pnpm | Plain SPA talking to a .NET API; fast dev server | Next.js, Create React App |
| .NET 10 SDK | Current LTS release | .NET 8 |
| Local MongoDB on port 27018 | Avoids clashing with any MongoDB already on 27017 | Shared cloud database |

## Out of scope
Real endpoints beyond `/api/health`, Docker images, Kubernetes Deployments,
auth. Those start in M1–M3.

## Verification
- Fresh clone on Windows (PowerShell) and one other machine: follow Commands in
  `CLAUDE.md`; `pnpm --dir web dev` shows the stub routes and
  `dotnet run --project api/ArcadeHub.Api` serves Swagger.
- A test PR shows the CI check, and `main` refuses a direct push.
- `/spike`: play, save, reload the page, load the save, and the game resumes
  from the same spot.
- `kubectl get ns arcade` works on all three laptops.
