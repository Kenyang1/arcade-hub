# Set up the repo so all three of us can build in parallel

- **Status:** in progress
- **Owner:** Kenyang (coordinator), with Soham and Khoi on their steps
- **Milestone:** M0 Setup, Oct 25–31 (see docs/spec.md)
- **Date:** 2026-10-21
- **PR:** <link once opened>

## Goal
By Oct 31, each of us can clone the repo, run the web app, the API and MongoDB
locally, and see CI pass on a PR. A homebrew game plays in the browser through
EmulatorJS, and a save state round-trips. The three contracts in the spec are
agreed, so M1 work can start in parallel on Nov 1.

## Context
The repo starts with `CLAUDE.md`, `docs/spec.md`, `docs/games.md`, this plan,
the PR template, `.gitignore`, `.gitattributes`, `.env.example` and
`docker-compose.yml`. No application code exists yet. Layout and commands are
defined in `CLAUDE.md`; build to match them exactly.

## Approach
Scaffold each workstream's folder with the smallest thing that runs and passes
its checks, then wire CI to run those checks. Pages and API share types
through `packages/contracts/`, written together from the spec's API table
(changed Oct 22 from mirrored .NET DTOs; see
`docs/plans/2026-10-22-express-backend.md`). The EmulatorJS spike runs in a plain page
inside the React app, so we learn early whether save states can be pulled out
and loaded back.

Rejected: Next.js for the web app (we don't need server rendering and the API
is a separate Express app), and a separate repo per workstream (contract changes would need
coordinated PRs across repos).

## Decisions
| Decision | Why | Rejected |
| --- | --- | --- |
| Vite + React + TypeScript, pnpm | Plain SPA talking to a separate Express API; fast dev server | Next.js, Create React App |
| Express + TypeScript API (changed Oct 22) | One language across the repo; Soham's proposal | ASP.NET Core on .NET 10 |
| Local MongoDB on port 27018 | Avoids clashing with any MongoDB already on 27017 | Shared cloud database |
| EmulatorJS 4.2.3, fetched file by file from `cdn.emulatorjs.org/4.2.3/` by `scripts/fetch-emulator.mjs` (loader, minified emulator, compression helpers, the `fceumm` NES core, the GPL license; about 3 MB) | Plain Node script, no archive tools, same on every OS; the version and core list are pinned in `web/package.json` under `config.emulatorjs` | The GitHub release asset (a 300 MB `.7z` with every core, needs 7-Zip); the `@emulatorjs/emulatorjs` npm package (ships only unminified sources and pulls `@emulatorjs/cores@latest`, every core, as an optional dependency) |
| `react-router` 7 | Version 8 needs Node 22.22 or newer; CLAUDE.md asks for Node 22 or newer and our laptops run 22.12 | `react-router` 8 |
| `oxlint` for `pnpm --dir web lint`, with `no-restricted-globals` banning `fetch` in `src/pages/` and `src/components/` | One dev dependency, what `create-vite` 9 ships; the `fetch` ban enforces the data contract in CLAUDE.md at lint time | ESLint with `typescript-eslint` and the React plugins (six dev dependencies and a config file for the same checks) |
| One `.env` at the repo root for both the API and the web app (`envDir: ".."` in `vite.config.ts`) | Matches the one-time setup in CLAUDE.md; Vite only exposes `VITE_*` variables, so API secrets never reach the browser bundle | A second `web/.env` |

## Out of scope
Real endpoints beyond `/api/health`, Docker images, Kubernetes Deployments,
auth. Those start in M1–M3.
